Predicting Population Changes in Czech Municipalities

Author: Tomáš Novotný

Date: December 31, 2025

Introduction

This report presents a machine learning project aimed at predicting the annual population change rate for municipalities in the Czech Republic. The goal is to leverage historical demographic data to forecast future population trends, which is crucial for local administration planning and resource allocation. The project follows the CRISP-DM methodology, covering data understanding, preparation, modeling, and evaluation. The primary objective is to predict the next-year total population change rate based on historical data from 1971 to 2020.

Problem Definition

The core challenge is to predict the next-year population change rate for each municipality, which makes it time-series problem. This target variable normalizes the population change by the municipality's size, allowing for a unified model across the whole country. The project hypothesizes that historical demographic trends (births, deaths, migration) and spatial relationships (region, location) contain sufficient signal to forecast future changes better than a simple baseline.

Data

The dataset for this project was sourced from the NI-MLP university course materials. It provides a historical record of demographic changes in the Czech Republic at the municipality level.

The dataset spans the period from 1971 to 2020 and is structured into two main components:

  1. Municipality Population Data: A collection of 77 files (organized by county) containing annual population counts and flow statistics (births, deaths, migration) for every municipality.
  2. GPS Coordinates: A supplementary dataset providing spatial coordinates (latitude, longitude) for mapping and spatial analysis.

The population data includes a secondary sheet named OD_KAM, which details multiple territorial changes in a single year. While this sheet may be valuable for verifying data integrity during the exploration phase, it was not directly used for modeling (due to low quality). However, the aggregate effects of these territorial changes are already captured in the main population data sheets.

Data Exploration and Quality Assessment

Extensive exploratory data analysis (EDA) was conducted to understand the data quality and structure.

Initial Cleaning and Standardization

During the initial data exploration, several observations were made and applied at the beginning:

  • Column Naming:
    • All column names were standardized to English names.
    • Inconsistent column names (e.g., 'KAM' vs 'Kam', 'Od kud' vs 'Odkud') were manually unified in two files (CZ0525, CZ0806)
  • Missings:
    • Numeric columns containing strings like "-" or "" were converted to NaN.
    • 195 occurrences of sequence "OPRAVA" were treated as missing values.
  • String Handling: Whitespaces were stripped from string columns.
  • Data Types: All numeric columns were cast to integer types.

Consistency Checks

The integrity of the dataset data was verified through the following checks:

  • Column Names: Verified that column names match across all files.
  • Uniqueness:
    • No duplicate records for (municipality_code + year).
    • All municipality codes are uniquely assigned to a single county.
    • Each row in GPS dataset has unique municipality code.
  • Geography:
    • All GPS coordinates (longitude/latitude) are within Czech Republic boundaries.
    • Postal codes (format 5 digits, range 10000-79999) and region codes (CZ NUTS 'CZxxx') are valid.
    • County codes are valid except for ['CZ020B', 'CZ020C', 'CZ020A'].
    • 4 county codes in 528 rows differ from the county codes in GPS data.
    • Only one municipality code from GPS file was not mapped (539996).
  • Naming Consistency:
    • 1:1 relationship confirmed for county_code_gps -> county and region_code -> region.
    • 169 municipality_codes found with more than one municipality_name.
    • 192 mismatches found between municipality_name and municipality_name_gps.
  • Population Data Consistency:
    • population_at_establishment is filled in 2112/6252 municipalities and once per municipality_code, and matches population_at_start_of_year.
    • Found 1550 municipalities with non-continuous year history.
    • Population Balance: The fundamental demographic equation (Start + Births - Deaths + Immigrants - Emigrants = End) holds true for >99% of the records (see Table).
    • Missing Values: A hypothesis that missing values in flow columns (births, deaths, etc.) represent zeros was tested and confirmed for >99% of cases.

Territorial Changes (Amendments)

A significant portion of the analysis focused on the "Amendment" columns (territorial changes due to splitting/joining). The data was split into amendment_df (single changes in one year and references to multiple changes in one year) and multi_amend_df (multiple changes, source OD/KAM sheet).

  • Inconsistencies in Filling:
    • amendment_df:
      • Found 3073 rows where population loss due to dividing and the causing municipality code are not consistently filled.
      • Found 3403 rows where population gain due to joining and the giving municipality code are not consistently filled.
    • multi_amend_df:
      • Found 3149 rows where population loss due to dividing and the causing municipality code are not consistently filled.
      • Found 3151 rows where population gain due to joining and the giving municipality code are not consistently filled.
  • Sign Errors: Significant number of incorrect signs were found and partially corrected:
    • amendment_df: Swapped values (10), Moved positive loss to gain (1318), Moved negative gain to loss (1926).
    • multi_amend_df: Moved positive loss to gain (1673), Moved negative gain to loss (1478).
  • Mixed Missing Values: Datasets contain rows with mixed NaN/non-NaN values in loss/gain columns
    • amendment_df:
      • 301 loss issues
      • 175 gain issues.
  • Reference Issues:
    • References to multi_amend_df were inconsistent (e.g., 'x2', 'x2+8') and normalized.
    • Expected sum of population changes in multi_amend_df did not match the reference in amendment_df in 96/1283 cases.
  • Hypothesis Testing: Tested 6 hypotheses (see Table) on what influences amendment values. The best match (Hyp 1: Intra-year, NO influence) only matched 73.6% of cases.

Modeling

The modeling phase focused on developing a predictive framework to forecast the next-year population change rate for each municipality. Given the temporal nature of the data, the problem was approached as a time-series regression task. The primary objective was to build a model that generalizes well across municipalities of varying sizes, from small villages to large cities. To achieve this, a robust feature engineering strategy was developed to normalize the data and capture historical trends, followed by the evaluation of gradient boosting models against a simple baseline.

Feature Engineering and Split

To prepare the data for time-series forecasting, several engineering steps were applied to ensure the models could learn temporal patterns independent of municipality size.

Feature Engineering:

  1. Normalization (Rates): All count-based variables (births, deaths, migration, total change) were converted to rates per capita (value / population at start of year). This allows the model to generalize across municipalities of vastly different sizes (from dozens to over a million inhabitants).
  2. Temporal Features:
    • Lags: Values from the previous 1, 2, and 3 years were added as features to capture immediate history.
    • Rolling Statistics: 5-year rolling means were calculated to capture longer-term trends.
  3. Static Features: county_code, region_code, latitude, and longitude were included to capture spatial dependencies.
  4. Target Variable: The target is the next year's total population change rate.
  5. Continuity Check: Only municipalities with at least 5 years of continuous history were retained to ensure valid rolling window calculations.

Note: Gradient Boosting models work well with categorical features, non-standardized data (do not require scaling), and highly-correlated features.

Data Split: A temporal split was used to strictly prevent data leakage from the future:

  • Train: 1993–2014
  • Validation: 2015–2017
  • Test: 2018–2019

Note: The years before 1993 were excluded due to Czechoslovakia split, which could introduce non-stationarities.

Selected Features: The final feature set included:

  • Spatial: latitude, longitude, region_code, county_code.
  • Demographic Rates (Current, Lags 1-3, Rolling Mean 5y): migration_population_change_rate, natural_population_change_rate, number_of_births_rate, number_of_deaths_rate, number_of_emigrants_rate, number_of_immigrants_rate, total_population_change_rate.
  • Other: log_population, year.

Training Strategy

Three approaches were evaluated:

  1. Baseline (Rolling Mean): A simple heuristic that predicts the next year's rate as the average of the last 5 years' rates. This serves as a benchmark for stability.
  2. LightGBM: A gradient boosting model tuned for robustness.
    • Objective: Huber loss (to be less sensitive to outliers).
    • Parameters: Learning rate 0.01, 3000 estimators, early stopping.
  3. XGBoost: A gradient boosting model using histogram-based tree methods.
    • Objective: Pseudo-Huber error.
    • Parameters: Learning rate 0.01, Max depth 7.

Both ML models were trained using Mean Absolute Error (MAE) and robust loss functions as the evaluation metric, acknowledging that population changes can have significant outliers due to administrative changes or specific local events.

Performance Evaluation

The models were evaluated on the Test set (2018-2019). We assessed performance both on the primary target (Rate per 1000) and the reconstructed Absolute Population Change.

1. Rate Prediction The Machine Learning models successfully outperformed the baseline in predicting the rate of change.

  • The Baseline's negative R2 indicates it fails to capture the variance in the rates better than a horizontal line (mean), whereas ML models show positive predictive power.

  • Median Performance: XGBoost has the lowest MedAE (5.36), meaning for the majority of municipalities, the ML prediction is closer to the truth than the Baseline (5.83).
  • Large Scale Performance: The Baseline dominates in RMSE and R2. This suggests that for large municipalities (which heavily influence squared errors), the simple "recent history" heuristic is extremely stable and hard to beat. ML models, by trying to predict complex rate dynamics, may introduce noise that scales up poorly for the largest cities.

3. Feature Importance

Feature importance analysis from the XGBoost model reveals that rolling means of total population change is the most influential predictors, followed by various migration-related features.

Conclusion: XGBoost is the preferred model for understanding local dynamics and predicting changes for the typical municipality (better MedAE). However, for aggregate national statistics or large cities, the 5-year rolling mean (Baseline) remains a highly competitive and stable predictor.

Conclusions

This project successfully demonstrated the feasibility of predicting municipal population changes using machine learning, while also highlighting significant challenges in data quality and scalability.

Key Findings

  1. Data Quality: The primary dataset required extensive cleaning. Specifically, the "amendment" data (territorial changes) was found to be highly inconsistent and was excluded. However, the implicit population changes were successfully reconstructed and imputed, resulting in a complete dataset for modeling.
  2. Model Performance:
    • XGBoost emerged as the best model for the "typical" municipality, achieving the lowest Median Absolute Error (MedAE). It effectively captures local dynamics and non-linear relationships.
    • Baseline (Rolling Mean) proved to be surprisingly robust, particularly for minimizing large errors (RMSE) and explaining overall variance (R2). This suggests that for large population centers, recent history is a very strong predictor that is hard to beat with complex models.
  3. Scalability: The discrepancy between MedAE and RMSE suggests that a "one-size-fits-all" model may not be optimal. Small municipalities behave differently from large cities.

Recommendations and Future Work

  • Hybrid Approach: For future deployment, a hybrid strategy is recommended: use the Baseline (Rolling Mean) for large cities to ensure stability, and XGBoost for smaller municipalities to capture more subtle trends.
  • Data Collection: Improvements in the reporting of territorial changes (amendments) are necessary to allow for more precise modeling of administrative shifts.
  • Additional Features: Incorporating economic indicators (unemployment rate, housing construction) could potentially improve the model's ability to predict migration patterns, which are currently the hardest component to forecast.
